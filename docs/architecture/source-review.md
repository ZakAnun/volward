# Function and call-site review against fd89c11

Review covers the plan through Task 10. This is an inventory and explanation of differences, not a formal proof of behavioral equivalence. Temporary raw comparisons are under `/private/tmp/volward-task10`; the tracked tables retain the conclusions.

## Mechanical moves and unchanged surfaces

- 71 Rust C export definitions (signature plus body) compare byte-for-byte equal across original `capi.rs` and the five families plus `capi/mod.rs`. Export names also match both macOS binaries exactly.
- 147 named Engine functions, including tests/helpers, compare equal after whitespace removal between baseline `engine.rs` and current parent/children. Helpers shared across modules retain `pub(super)` where needed; same-file AI helpers are private. The AI method documentation moved to the described method. Task 10 only corrects cache-invalidation commentary; locks, fields, allocation, async publication and counters are unchanged.
- 134 FFI typedef names/signatures from original `native_bridge.dart` remain unchanged. Its bridge classes, initialization, lookups, fallbacks, loader and ownership logic are unchanged. An inventory across the entire bridge directory also sees the pre-existing worker alias `VolwardScanBridge`, which is not a new ABI binding.
- `ScanSortMode` retains enum order and Rust names. Browse widgets move with import and enum-import changes; `BrowseResultsPane.build` is unchanged. Shared query/tree/cache APIs remain at their actual paths.
- Core, AI Rust library, index-pb, desktop platform, CLI, website, release scripts/workflows, Cargo manifests/lockfile, rules, protobuf, SQL migrations and tracked FVM files have zero baseline diff.
- Existing tests are retained; import/format-only test changes accompany moved paths. Added tests cover catalog isolation/global compatibility, provider resolution, page/coordinator ownership/handoff/stale completion, delete handoff and ledger ordering/failure. Test fixtures also adapt to explicit owner injection.

## Platform service changes

- `quota`, `analyze`, `synthesize_conclusion`: HTTP authentication/validation remain in handlers; plain arguments enter application functions, plain responses are wrapped with `Json` on return. Borrowed authenticated user ID replaces an unnecessary owned clone. Validation still rejects over-150 before empty and precedes debit. Request count is computed from the same selected vector after validation.
- `balance`: extracts the same two-column SQL read and environment selection at the same call positions. Quota totals query remains unchanged; analyze reads balance after upstream success; synthesis serializes before charge and has no success balance read.
- `debit_one_credit`, `refund_one_credit`: whitespace-normalized source matches baseline proxy bodies, including SQL, bind order, immediate transaction, error rollback and commit. Root billing exports and proxy compatibility exports point to these functions. Task 10 makes only the new ledger module private.
- Task 10 removes an observed reverse dependency from application to handlers: DTO definitions and `AnalyzeRequest.validate` move byte-for-byte to private `ai/types.rs` (validation becomes `pub(super)`). Handlers re-export the original public names; application imports the shared types directly. HTTP handler bodies and service bodies are otherwise unchanged.
- Auth/device/billing call-site changes use root authorization/balance re-exports. Router and externally observable wire/error contracts are unchanged.
- New tests observe committed debit inside upstream for analyze and synthesis; verify failed charge prevents upstream, failed upstream refunds, and a SQLite trigger that aborts refund insertion rolls back the partial balance refund while preserving the original 502 error on both routes. The trigger is confined to temporary test DBs.

## Acceptance decision

Mechanical Rust/FFI moves and Session scan/browse/delete adaptations are accepted with the recorded tests and source comparisons. AI owner-isolation changes are explained and tested but **not unconditionally accepted as behavior-identical for every baseline concurrency race**; D7/D8/D11 identify the exact limit. This audit does not silently label those changes as path-only. Website type checking and native packaging remain explicitly unaccepted as detailed in the delivery record. No unexplained source-difference group remains in the reviewed plan inventory.

## Final fix-wave update

The final fix wave changes Coverage retirement error handling, pending-start coordination, provider ownership, owner-bound resume plan lookup and native Coverage borrower lifetime. These are behavioral corrections and are not covered by the earlier mechanical-equivalence counts. On the cooperative path, retirement drains admitted execution and awaits service shutdown, including isolate host and worker teardown. Cleanup continues after errors and preserves the first failure. Focused tests exercise injected retirement phase failures, controls during a second pending start, same-ID owner handoff, controlled-bridge Session disposal during plan polling and main-isolate verdict backfill, and a service draining active/pending work. Task 12 exercises the production worker command loop with a native bridge fixture. Successful worker shutdown with the production dylib remains unverified. A live noncooperative worker can keep retirement pending, and fatal worker teardown uses best-effort cleanup. The isolate backfill itself, other legacy Session borrowers, and all concurrency interleavings remain outside this proof. See the final fix and Task 12 reports for command-level results.
